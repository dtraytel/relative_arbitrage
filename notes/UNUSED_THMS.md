Refreshed 2026-10-14 for the session layout of `PLAN_RESTRUCTURING_3.md`
(phase 8). The list of 166 "unused" theorems this file used to carry named
theories that no longer exist (`Exit_Class_DPP`, `Value_Function_Viscosity`,
`Comparison_Principle`, the market layer, …) and was measured against no
declared roots; it is in the history of this file (any commit up to
`f2da170`).

## The rule: dead-code passes run against `notes/review_3/roots.txt` only

A fact is dead when it lies outside the closure, by proof terms, of the facts
named in `notes/review_3/roots.txt`. Nothing else counts as a root: not "used
by some theory", not "imported by the statement", not "a library session".
Never run a pass without these explicit roots; the last unrooted pass deleted
the symmetric-part lemma that the statement's prose relied on.

`roots.txt` has 523 entries, one per line, as `Theory.fact` or as
`Session.Theory.*` (every proper fact of that theory). It holds:

- the theorems of the statement session: `Theorem_1_1_Statement`,
  `Paper_Readings` and `Paper_Map` (one theorem per numbered item of the
  paper, so the reader's index and the root set cannot drift apart);
- the evidence lemmas the statement's prose cites;
- for each library session, the deliverables its `ROOT` description and
  `document/root.tex` advertise (`notes/review_3/data/library_deliverables.md`);
- the results of independent interest kept by the owner's directive of
  2026-10-07 (`PLAN_RESTRUCTURING_3.md` §1.3: KEEP_ROOT, KEEP_EVIDENCE,
  FIX_THEN_KEEP, KEEP_API and the COROLLARY verdicts that keep their name;
  `notes/review_3/data/independent_interest.md`).

Changing the roots:

- A fact leaves `roots.txt` only in a commit of its own, saying why.
- A theory or fact rename updates `roots.txt` in the same commit, and every
  fact rename is appended to `notes/review_3/renames.txt` (`old new`, names
  without their theory qualifier), which the fingerprint check
  (`fp_compare.py`, `Review_Analysis.thy`) reads.
- Every entry must resolve. `Review_Analysis.thy` reports the root names that
  do not resolve; the count must be zero.

## How to run a pass

1. `notes/review_3/check.sh [OUTDIR]` builds every session (`-D .`), then the
   throwaway session `Review_3_Analysis` (`notes/review_3/ROOT`), whose
   `Review_Analysis.thy` reads the roots, checks that no oracle occurs in
   their proofs, computes their closure and writes `facts.tsv`; `dead.py`
   turns that into dead lines per theory. **Caution:** `Review_Analysis.thy`
   reads `roots.txt` (and `renames.txt` beside it) from an absolute path
   (`rootsfile`, marked `(* ROOTS *)`); in another worktree, point it at that
   worktree's file, or the pass runs against the wrong roots.
2. Before deleting a whole theory, grep it for global `declare`,
   `lemmas … [simp]`, `[measurable]`, `notation`, `interpretation` and `setup`,
   and re-home each one (`PLAN_RESTRUCTURING_3.md` §3).
3. `delete_dead.py` deletes lemma blocks with no live fact and no remaining
   mention in code, texts that mention only deleted facts, headers left empty,
   and unused definitions named nowhere else. Antiquotations naming deleted
   entities become plain prose.
4. Build everything, and repeat until a pass finds nothing: deleting a theorem
   frees its private helpers.

Filters that still apply (each earned its place by a mistake):

1. **Facts generated by `interpretation`** are reported under the locale's
   name; matching them back by short name conflates an inherited copy with the
   original. They are kept.
2. **A fact named in the source is not dead**, even when no proof term uses it.
   A fact listed in a `simp add:` that simp did not need leaves no proof term,
   yet deleting it breaks the build with `Undefined fact`. The same holds for
   `@{thm}` antiquotations. Such a mention can be removed first; then the fact
   goes.
3. **A lemma block runs to the next top-level command**, which swallows the
   `(*<*)` before a closing `end` unless trailing blank and comment-marker lines
   are trimmed back.

The former third filter, "paper-specific sessions only", is gone: the library
sessions now have explicit roots (their advertised deliverables), so a library
fact outside the closure is dead too.
